# 本地区分说话人（测试版）

分支：`codex/speaker-diarization`。从稳定标签 `continuous-reader-v1.0.0`（`14deaa71ea755947c51d08ee304cb6fe619effcd`）开发，保留原连续阅读分支和稳定程序。

本版可从电脑播放声音中区分匿名说话人，仍处于测试阶段。常规双人、三人固定音频通过了本次 90% 的归属门槛；快速短句接话尚未通过，重叠检测也不可靠。因此本版**未标记为全部验收通过**，不替换原稳定版。详见[测试记录](说话人测试记录.md)。

## 使用方法

1. 在 Windows 11 上运行测试包中的 `LiveCaptionsTranslator.exe`。自包含 x64 程序不需要另装 .NET。
2. 主窗口 Setting 中保留原翻译服务，目标语言选择中文。
3. 在连续阅读窗勾选“区分说话人”。默认关闭。首次开启自动下载模型，状态行显示下载、校验、解压和加载进度。
4. 声音设备默认“跟随系统播放设备”；也可以选择 Zoom 或视频实际输出的设备。本模式只使用 WASAPI 播放回环，**不采集自己的麦克风**。
5. 正在识别的英文先出现在底部待确认区，通常约 6–7 秒后加入历史。确认换人时立即另起双语块，显示“说话人 A／B／C”；译文随后回填。
6. 同一人继续讲话时，仍按“每条长度”和“停顿分段”合并。这里的停顿使用音频时间；Windows 模式使用字幕原文更新时间。
7. 无法确定时显示“未确定”；检测到同时讲话时显示“多人重叠”。不能分离重叠的两路文字，也不识别真实姓名。
8. “重新编号”开始新会话。重启、重新开启模式、切换播放设备也开始新会话，编号从 A 开始。旧历史保留。
9. 取消勾选返回 Windows 实时字幕。模型或采集失败也会保留已识别文字并返回普通模式，状态行显示原因，可重新勾选重试。

电脑同时播放的其他声音也会进入所选输出设备。新模式的识别、分人、标点均在本地 CPU 运行；翻译继续调用你已选择的原有服务，文本发送行为与该服务一致。

## 阅读、复制和导出

英文在上、中文在下。确认后的条目不因后续声音分析重新编号或重排。向上回看时继续保存新记录，“回到最新”恢复跟随。关闭阅读窗不停止录音和记录；关闭主窗口才退出。

“复制双语”包括说话人、时间、原文和译文。“导出 CSV”有两种格式：

- **原五字段**：Timestamp、SourceText、TranslatedText、TargetLanguage、ApiUsed，兼容原格式。
- **含说话人**：在原五字段后追加 SessionId、Speaker。同一会话的 A 才代表同一匿名身份；不同会话的 A 不应视为同一个人。

两种格式都按完整段落聚合，导出全部历史。首次加载最近 200 段，上翻每次 100 段；一个段落不会拆到两页。

## 模型与存储

模型清单为 [manifest.json](../src/speech/models/manifest.json)，包含固定下载 URL、压缩包与每个推理文件的大小及 SHA-256。首次下载总量约 558 MiB，实际选用的推理文件约 231 MiB。清单不匹配时拒绝加载并提示重试。模型放在程序旁的 `models/speaker-v1`；本机交付目录可预先放置已验证的模型，无须重复下载。

| 用途 | 固定模型 | 推理版本 |
| --- | --- | --- |
| 英文流式识别 | sherpa-onnx-streaming-zipformer-en-2023-06-21 | encoder / decoder / joiner INT8 |
| 说话人分段 | sherpa-onnx-pyannote-segmentation-3-0 | model.onnx |
| 声音特征 | nemo_en_titanet_small.onnx | ONNX |
| 英文标点及大小写 | sherpa-onnx-online-punct-en-2024-08-06 | INT8 + bpe.vocab |

运行库固定为 NAudio 2.2.1、org.k2fsa.sherpa.onnx 2.0.1；该 x64 包带 ONNX Runtime 1.28.2。许可证及来源见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

音频统一为 16 kHz 单声道。识别和分人共享累计采样时间，静音也推进时间轴；每 2 秒分析最近 10 秒，最近约 6 秒保持待确认。音频环形缓冲 30 秒、采集缓冲 3 秒、待处理队列最多 60 个 100 ms 块。超过积压限制会明确停止新模式。原始声音不写入录音文件，声音特征仅在本次会话内保留，最多 32 个原型。

`setting.json` 和 `translation_history.db` 默认固定在程序目录。本次同时修复单文件发布把数据和模型写入临时解包目录的问题。新库只增加可空的会话、来源键、说话人状态及音频起止列，以及待确认草稿表；旧历史原样读取。正式记录和剩余草稿在同一 SQLite 事务内写入，来源键避免重放重复入库。正常停止处理尾部缓冲；异常退出后，下次启动将尚未确认的原文恢复为“未确定”。翻译未完成时仍保留原文。

## 使用已有历史

先退出旧程序，再备份 `setting.json` 和 `translation_history.db`。可以在新程序启动时指定旧数据目录：

```powershell
.\LiveCaptionsTranslator.exe --data-dir="D:\旧程序的数据目录"
```

不要同时运行两个程序写同一个历史库。测试包不包含你的设置、API 密钥或个人历史。本机的 `artifacts/启动说话人测试版.cmd` 使用 `artifacts/speaker-user-data` 中的原设置与历史副本，继续保留原有记录。原版数据及程序保持原样；测试版新增记录保存在该副本中。旧版单文件数据若位于 .NET 临时解包目录，应先复制到长期保存的目录再使用，避免临时清理造成丢失。

## 开发与复现

需要 .NET 8 SDK 和 Windows x64：

```powershell
dotnet run --project tests/Reader.Tests -c Release
dotnet build tests/Speaker.Integration -c Release
.\scripts\test-speakers.ps1 -DownloadFixtures -InstallModels
.\scripts\test-speakers.ps1 -Soak
.\scripts\publish-speaker.ps1
```

测试脚本使用独立的带时间戳输出目录。LibriSpeech 固定音频、模型及测试数据库不进入 Git。播放一次固定音频进行真实回环检查：

```powershell
.\LiveCaptionsTranslator.exe --speaker-test --data-dir="D:\独立测试目录" --speaker-model-dir="D:\模型目录"
dotnet run --project tests/Speaker.Playback -c Release -- "artifacts/speaker-test-时间戳/fixtures/clean-three.wav"
```

`--speaker-test` 开启真实电脑声音采集，但使用明确的示例译文，不能用于评价中文翻译质量；必须指定隔离数据目录。正常使用不传该参数。

## 当前限制

短于约 1–2 秒的回应、快速轮换、相近声音和多人同时讲话可能被合并、错认或标为未确定。识别器的词时间也有偏移，换人边缘可能形成很短的未知块。已确认记录不会追溯修正这些模型错误。局部模型最多同时处理 3 个说话人槽位，并不能保证复杂会议的准确率。

固定测试音频来自朗读语料，经拼接和混音构造，不代表真实 Zoom 会议。普通场景结果不能替代快速接话、噪声、设备切换及真实会议的进一步验证。
